Six stages. One artifact each. A human gate between.

Every stage reads its skill file, produces exactly one artifact, and stops at the gate. You approve the artifact; only then does the next stage start. Stage 6 turns any incident into the next intent: the loop feeds itself.

  1. Intent intent.md

    The agent explores first, then grills you until the intent is exact and evidenced.

  2. human gate · approve intent

  3. Spec spec.md

    Generated from the intent, adversarially reviewed before it reaches you.

  4. human gate · approve spec

  5. Plan plan.md

    Read-only: which files change, in what order, with what proof it worked.

  6. human gate · approve plan

  7. Build code + tests

    The plan executed with verification woven through, not bolted on at the end.

  8. checks green · no gate

  9. Ship evidence.md

    Adversarial review plus evidence; you approve the release by reading what was flagged.

  10. incident triggers · no gate

  11. Maintain intent.md + lesson

    An incident becomes a diagnosed intent and a recorded lesson, not a vague complaint.

  12. writes the next intent.md

A production issue in stage 6 writes a new intent.md. People triage and review the work; they no longer start it.

What the gates buy you

The kit is small on purpose. Everything it adds sits between your decision and the agent’s next move.

Grilled intents
Stage 1 explores before it asks, then labels every claim in intent.md [verified] with evidence or [assumed] with a reason. Users can be mistaken; this is the cheapest stage to find out.
Tamper-evident gates
approve.sh records the artifact’s sha256; one quiet edit after approval and the next check-gate.sh prints GATE CLOSED on its own.
Delegation stays visible
An agent may run the approval only on your explicit words in chat. The record then carries mode: delegated-chat, so the keystrokes were never silent.
Fresh-context review
A verifier, an adversary, and a researcher each meet the work in a context that did not author it (report only, fix nothing), so a soft pass can’t coast on the author’s optimism.
AS-IS → TO-BE specs
Specs pair what actually happens today (file:line evidence) with what happens after the change. The delta between the columns is the change.
Memory that stays bounded
Mistakes land once in a ≤50-line INDEX.md, then get promoted into the skill that prevents them. Read one index; never repeat a lesson.
Plain speech, by rule
Rule 8: every message to a human starts with context, keeps to short active sentences, and ends with the one decision you owe.

Three commands, then hand it your harness

No installer, no daemon. The kit directory stays framework-only; your project gets a .sdlc/ whose artifacts version with your code.

  1. git clone https://github.com/cskwork/sdlc-kit ~/sdlc-kit

    Once per machine. That’s the whole install.

  2. cd /path/to/project ~/sdlc-kit/init.sh

    Seeds .sdlc/ (work, approvals, memory, config). Then fill in your real build, test, and lint commands in .sdlc/config.md.

  3. tell your harness: “read ~/sdlc-kit/AGENTS.md and follow it”

    One pointer line in your project’s agent file does it. Pick your harness below.

Honest limit: tamper-evident, not tamper-proof

Approval records catch post-approval edits and mistakes: the sha256 mismatch is mechanical. A malicious agent forging records is a different threat. That line is held by agent rules and by the git history of .sdlc/approvals/. Approvals are committed with the code, and that history is the real audit trail.
