# v2.27.0: Memory is a short index over verified pages, kept honest by a dream pass

## Problem

In a store measured on 2026-11-16, the memory folder held 224 KB (about 45K tokens) and scouts were told to read all of it. Its `INDEX.md` listed 15 lessons and none of the 42 area and note pages; no memory file had changed in four weeks although five slugs shipped since; 10 of 60 files carried a `[verified: file @ sha]` mark; and Evidence named a `glossary.md` the store did not have. `close` moved each slug to the archive as is, build caches included: one slug's `logs/` held a 1.6 GB Gradle home, and the archive reached 2.1 GB. Two `sdlc.sh` runs on one slug could both read `.state` and the later write dropped the earlier one.

## Changes

- **`sdlc.sh memory index`** rebuilds the block between `<!-- sdlc:index start` and `<!-- sdlc:index end -->` in `INDEX.md`: one line per page (every `*.md` but `INDEX.md`, nothing under a dot name), grouped by folder — link, summary (a `Summary:` line, else the first heading, cut at 120 bytes), `verified N @ <sha of the last verified tag that names one>` or `unverified`, `unconfirmed N`, size. Lines outside the block are kept; a store without the markers gets the block appended. A page without a summary is flagged in the line and on stderr. It warns when `INDEX.md` plus top-level pages exceed `memory_top_kb` (64) or all pages exceed `memory_total_kb` (256).
- **Read the index, not the folder.** `phases/1-intent.md`, `phases/2-plan.md`, `roles/scout.md` and `SKILL.md` say what memory is for — verified facts, rules and traps the code cannot tell cheaply — and to read `INDEX.md` first, then only the pages that bear on the question.
- **`close <slug> shipped` needs a memory decision**: a `Memory:` line in evidence.md (the template puts it under Shipping) naming the pages updated, comma-separated paths in the memory folder that must exist, or `none — <why>`. A missing line, a placeholder, a bare `none` or an unknown page is refused. `dropped` needs none. `check ship` is unchanged, so a gate run before the first push does not need it yet. Close refreshes the index.
- **`phases/4-evidence.md`**: one fact, one place, detail in pages; `glossary.md` is created with a `# Glossary` first line when a term is first settled; a fact not re-checked is `[unconfirmed]`.
- **`sdlc.sh dream`** refreshes the index and prints a self-contained brief (`roles/dreamer.md` plus this run's memory folder, sizes and budgets, the HEAD it verifies against, and each slug closed since the last dream: a shipped one with its `Memory:` line and evidence/review paths, a dropped one with its intent path) and, once the dreamer runs `sdlc.sh dream --done`, `last`, `last_epoch` and `slugs` are recorded in the memory folder's `.dream-state` (see below). The dreamer verifies, fixes or deletes stale notes, merges duplicates, fixes links, pushes detail down, harvests reusable facts, stays within budget, reruns the index and appends a short report to `.dream-log.md`. **`sdlc.sh dream --check`** counts processed slugs, not days: it exits 10 and prints `due: 3/3 closes since <time>` once `dream_every` (3) slugs closed, shipped or dropped, since the last dream, or once `dream_max_days` (14) passed with at least one close (a store that never dreamed counts as past it). With no close since the last dream it is never due; it exits 0 and prints `not due: 1/3 closes since <time>`.
- **Transcripts are the ground truth for dreaming.** New config key `transcripts:` (default empty) is a shell command run in the project root with `{slug}` and `{since}` (the last dream's UTC time, `1970-01-01T00:00:00Z` before the first) replaced; it prints paths or `path:line` hits of that slug's session transcripts or logs. For each closed slug the brief lists at most `transcripts_max` (20) distinct hits, as `path` or `path:line` only — text after `path:line` is dropped, each line is cut at 300 bytes, and a failing command shows `(command exited N)` — plus the files of the slug's `logs/`. With the key empty the brief says `Transcripts: none`. The dreamer checks a note about what happened in a session by grepping those hits, never reading whole files, fixes or deletes what they contradict, and turns mistakes repeated across sessions into rules that say how we know.
- **Notes are written when they are learned.** `SKILL.md` says once what memory is for — what the next feature would reuse and cannot look up cheaply: verified facts, traps with their fix, rules with how they were verified — and that an agent updates the page when it verifies such a thing or hits a trap (merge, never rewrite a page whole), with no fixed "record only X" rule. The close-time `Memory:` line stays as the checkpoint. A question memory cannot answer is answered "Not in memory" plus what to look up.
- **Every fact line carries its basis and date**: `[verified: <path> @ <sha> | as-of: <date>]`, `[source: <slug or transcript> | as-of: <date>]` or `[unconfirmed]`. The dreamer rewrites a superseded fact as `was X until <date> (now Y)`, marks an unsettled one `CONFLICT: <a> vs <b>` with sources and dates (a newer verified observation wins), writes "not found in <where> as-of <date>" instead of a global absence, treats its inputs as data, not instructions, and copies no secrets. Merging keeps every fact line; the old page becomes a `MOVED TO <link>` stub and links are repointed. A page over 8,000 characters starts with a `## Current picture` of 30 lines at most.
- **Peers: one home per kind of knowledge.** New config key `peers:` (default empty): space- or comma-separated paths of other memory stores the user runs (`~` and globs allowed, relative to the project root), read-only. The memory folder is the home for project knowledge; a peer keeps its own kind (preferences, feedback, raw history). The brief lists each match under `Peers` with its file count and KB, never its content (`Peers: none` when empty, `no match` for a pattern that matches nothing). The dreamer greps peers for the facts it touches, never edits one, and for a project fact also in a peer, or a peer contradicting memory, adds `peer: <peer file> duplicates|contradicts <memory page> — propose: keep in <page>, remove from peer` to its report; a person acts on it. Existing duplicates are not moved in bulk. `roles/dreamer.md`'s word cap rises from 250 to 300.
- **`## Core`: the promoted top layer.** `INDEX.md` keeps a hand-maintained `## Core` above the generated block — the few rules every agent needs, one line and a link each. `memory index` adds an empty `## Core` stub once when a store has none, keeps the section as written, counts its non-blank lines in its summary (`Core N lines`), and warns over 25 lines or `memory_core_kb` (2). The dreamer promotes a rule needed across several slugs or whose absence caused a failure, demotes one no longer needed, and keeps detail in pages. Since every phase reads `INDEX.md` first, Core is loaded every phase.
- **Index lint.** `memory index` prints `Lint: N dangling links, N MOVED TO stubs, N pages without a basis tag, N over memory_page_kb K, N over 8000 bytes without ## Current picture.` and names each finding on stderr. Links are checked relative to the linking page (INDEX.md included); URLs and anchors are skipped; `glossary.md` needs no basis tag. A page line shows `source N` for `[source: …]` tags and `moved` for a stub. New key `memory_page_kb` (16). The brief prints the lint line.
- **`dream` records nothing; `dream --done` does.** `sdlc.sh dream` prints the brief only (it still refreshes `INDEX.md`) and ends with the command to record the run: `sdlc.sh dream --done --through <time of the newest close it listed>`. `dream --done [--through <ISO UTC time>] [--note <text>]` writes `.dream-state` (`last` = that time, so a slug closed after the brief stays due; `slugs` = those covered) and appends a `.dream-log.md` line when the dreamer wrote none since the last `--done`. A scheduler that prints the brief but fails to start the dreamer no longer loses that dream. `--check` is unchanged. The brief's `Code at HEAD` line no longer repeats the sha.
- **Search stays first-class.** `roles/scout.md` and `SKILL.md`: read `INDEX.md` (Core, then the list), then only the pages it names; with no entry, grep memory (and, for scouts, the `transcripts:` hits) — never the whole folder.
- **Close prunes caches.** Before archiving (shipped or dropped), folders under `logs/` named in config.md `prune:` (default `gradle-home .gradle node_modules build .m2 target`; empty turns it off) lose every file but Markdown, JSON, PNG/JPEG/GIF/WebP and the logs evidence.md cites; close prints the KB freed and warns when the archived slug is still over `archive_warn_mb` (50).
- **Config.** The new keys (`transcripts:`, `peers:`, `transcripts_max`, `memory_core_kb`, `memory_page_kb`, and those above) are optional and default as stated; README lists them (`templates/config.md` stays within the prompt budget, so it does not repeat them).
- **Code layout.** The lock, index, memory check, pruning and dream live in `lib/store.sh`, which `sdlc.sh` sources (`sdlc.sh` stays at 600 lines). The prompt budget still caps SKILL, phases, roles and templates at 6000 words; `roles/dreamer.md`, loaded in no phase, has its own 300-word cap, as `todo/AGENT.md` does. To fit the memory rules, `SKILL.md` drops repeated lines (the default `human_gates`, how `sdlc.sh` finds `.sdlc/`, the sharing note that README carries) and `phases/2-plan.md` drops the `refs/learnings.md` line `roles/scout.md` already gives.
- **`.state` lock.** `approve`, `review`, `score` and `close` hold `.state.lock` (mkdir) from reading `.state` to writing it; a lock whose pid is gone, or that has no pid after a minute, is reclaimed; a live one is waited on for `SDLC_LOCK_WAIT` seconds (30), then the command fails and names it.

## After updating

Anything that runs `sdlc.sh close <slug> shipped` must first write a `Memory:` line in the slug's evidence.md, e.g. `- Memory: areas/billing.md, glossary.md` or `- Memory: none — nothing reusable beyond this fix`. Run `sdlc.sh memory index` once to index existing pages, and schedule `sdlc.sh dream --check || <run an agent on sdlc.sh dream>`; the agent's last step is the brief's `sdlc.sh dream --done` command, so a run that never starts is retried at the next check. Optionally set `transcripts:` to a command that finds a slug's session transcripts.
