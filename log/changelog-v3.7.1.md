# v3.7.1: One ask per card, build outputs left out of the dirty check, no organisation traces

## Problem

- **Several asks on one card.** When an agent left a question (`waiting`) or a command (`exec`) on a ticket, the board and the list could show it next to the kit's own instructions for the agent: an sdlc action such as "ship to stg, then sdlc.sh ship … <sha> [repo]" or "run QA on S1 S2 S3, fill evidence.md, sdlc.sh score", sometimes with raw check text from sdlc status ("How sure we are table missing…"). On 2026-11-25, 4 of 5 cards waiting on a person showed two or three instructions at once, and the person had to guess which one was theirs. A work document's older "Your call" could also replace the agent's question on the board.
- **A local build output blocked score.** On 2026-11-23, `sdlc.sh score` refused with "dirty tree" because an untracked build output (`dist-dev/`) sat in the worktree. Only a person could delete it, so the line stopped.
- **Organisation traces in a public kit.** Code comments and tests held a company Atlassian domain and internal ticket keys.

## Changes

- **One ask (board panel, list, details).** When a card is the person's turn because an agent asked (`waiting` or `exec`, not an approval gate), its question is the only ask shown. The kit's sdlc actions of the card's members and the feed's `nextStep` move into a closed `<details>` "What the agent does next / 에이전트가 이어서 할 일" under the reply box, and More no longer repeats the next step. In the list, a row whose agent asks shows that question (or the run ask, for a command alone) with its own kit action folded the same way. A row that only carries the kit instruction for the same work (the same sdlc slug) as another row's question folds too; a row for other work keeps its own NEEDS-HUMAN step visible as the person's task. The details pane shows the item's kit action closed under "Your next step". The sdlc work document's "Your call" no longer replaces the agent's question; a brief's still does. A card with no agent question (a pure sdlc NEEDS-HUMAN, or a gate) is unchanged. New helpers `agentAsks`, `sameWork` and `agentNextOf` in `todo/status.mjs`.
- **`artifacts:` in config.md.** An optional key lists untracked build outputs as globs relative to each repository's top, as git status lists them (`artifacts: dist-dev/, coverage/`). The dirty-tree check of score and check ship, and the change `review --uncommitted` binds, leave matching untracked paths out, and one warning names them: `ignoring untracked build artifacts in <repo> (config.md artifacts:): dist-dev/`. Tracked or modified files always count; without the key nothing changes. The README warns that a broad glob such as `*` would also hide an uncommitted source file. The logic lives in `lib/store.sh` (`skip_artifacts`); `sdlc.sh` gains one call and stays at 600 lines.
- **Public-trace guard.** Company domains and internal ticket keys are replaced with `example.atlassian.net` and `PROJ-123`-style keys; test meaning is unchanged. `tests/public-trace.sh` fails (exit 1) when any tracked file, changelogs included, matches a pattern in `tests/public-trace.patterns` (one extended regex per line, case-insensitive), and exits 2 when `git grep` itself fails, so a bad pattern never passes silently. CI runs it before the selftest. Two older changelogs were reworded to drop the traces.
